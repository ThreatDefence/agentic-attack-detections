# What RedAmon leaves behind

RedAmon ([samugit83/redamon](https://github.com/samugit83/redamon), MIT license, first commit December 29, 2025, reviewed at `73ca9d38` (version 7.9.0, committed November 19, 2026) on November 23, 2026) is a self-hosted penetration testing platform: a Docker Compose stack with a Next.js console, a recon pipeline that writes an attack surface graph to Neo4j, and a LangGraph agent that exploits what the graph shows from a Kali container. It had 3,471 GitHub stars, 742 forks and 3,586 commits on the review date. The maintainer is Samuele Giampieri. File references are to the repository at `73ca9d38`.

**Fragility** says what it takes to remove a signal: *code* means editing RedAmon, *config* means a `.env` value, a compose value or a project setting in the console, *operator* means a choice made at run time.

Lines marked *(inferred)* were not read from the code or could not be checked without running it.

## What has been seen in the wild

- No vendor or CERT report of RedAmon used in a real intrusion was found in searches on November 23, 2026.
- **VulnCheck** (November 16, 2026) published CVE-2026-129855 for GHSA-3cjg-8cp8-j269: before 7.8.0 the sandbox terminal server on port 8016 gave an unauthenticated root shell over WebSocket. Credit: Dilanka Kaushal Hewage. A second VulnCheck entry covers missing authorization on agent session routes in 4.0.0 to 7.8.0. These are flaws in RedAmon, which matter to anyone running it and to anyone who finds an exposed one: https://www.vulncheck.com/advisories/redamon-before-7.8.0-unauthenticated-root-shell-via-terminal-pty-websocket . The repository names the same advisory at `docker-compose.yml:796-798`; version 7.8.0 is dated November 11, 2026 in `CHANGELOG.md`.
- **Cyber Security News** (June 29, 2026) described the tool and its approval steps and reported no attacker use: https://cybersecuritynews.com/redamon-ai-tool/
- No public detection rules for RedAmon were found.

## What the code does not contain

RedAmon ships no implant, C2 protocol or persistence of its own. Post-exploitation runs through stock Metasploit handlers and payloads (`exploit/multi/handler`, meterpreter, `web_delivery`, msfvenom files named `payload.exe`, `payload.elf` and so on), netcat or socat shells, and the Kali tools, so anything on a compromised host looks like Metasploit or the tool the agent chose, not like RedAmon. It has no telemetry or license check; the only call home is the version check against GitHub. It has no chat-platform bots and no built-in proxy rotation or Tor. Its phishing skill builds payloads and documents with Metasploit and tells the agent to send mail with Python `smtplib` (`agentic/prompts/phishing_social_engineering_prompts.py:77-247`). The names, ports and strings above are defaults of the stock code, and an operator who edits the code can change them.

## Behind Basic authentication

Operators put nginx Basic auth in front of the RedAmon console and name the realm after the tool. In Shodan on November 25, 2026, 3 services answered `401` with a realm that starts with `RedAmon`, on port 443. The realm is set by the web server in front of the console, so a match is probable, not certain. The exposure search `basic auth realm (probable)` finds them, and Suricata 3801043 and the Zeek behavior `AgenticBehaviors::Agent_Console_Realm` match the realm on your own network.
